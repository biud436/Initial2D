# 9단계: 데모 재작업과 이벤트 커맨드

> 문서 번호가 10인 이유: 09는 교차 절차인 검수 문서([09-testing.md](09-testing.md))가 쓰고 있다.
> 로드맵의 단계 번호로는 **9단계**다.

**권장 모델**: Claude Fable 5 — 1절의 이벤트 커맨드 데이터 모델이 앞으로의 에디터 연동과
저장 포맷을 좌우한다. 아키텍처 판단의 비중이 큰 단계다 (index.md의 모델 선정 기준). 쓸 수
없으면 Opus 5.

> 목표: 이슈 24의 요구를 만족시킨다. **기획서대로 만든 데모**와, **에디터가 만들어 낼 수 있는
> 이벤트**다.

## 1. 배경 — 8단계는 무엇이 부족했는가

8단계는 "타이틀에서 시작해 대화하고 집을 드나드는 게임이 돌아간다"를 증명했다. 이슈 24는
그것이 **기술 데모**이며 게임이 아니라고 지적한다. 구체적으로 셋이다.

| 지적 | 8단계의 상태 | 이 단계에서 |
|---|---|---|
| 기획서가 없다 | `08-demo.md`는 개발 계획서다 | [docs/design/port-town.md](../design/port-town.md) 작성 완료 |
| 의미 없는 대사와 맵 배치 | 대사는 기능 시연용, 맵은 난수 장식 90개를 뿌린 십자로 | 기획서의 항구 마을을 손으로 설계해 다시 만든다 |
| 이벤트 커맨드가 범용적이지 않다 | 이벤트는 `script = function(self, ctx)` 인 Lua 함수 — 에디터가 만들 수도 읽을 수도 없다 | 데이터 커맨드 목록으로 적고, Lua 함수는 탈출구로 남긴다 |

여기에 이슈의 "실제 모바일과 PC에서 플레이 가능해야 한다"가 더해진다. 8단계의 모바일
조작은 "패드 밖 아무 데나 탭 = 결정"이라 대화와 이동이 서로를 방해한다.

## 2. 마일스톤

순서에 의미가 있다. 커맨드가 먼저 있어야 기획서의 이벤트를 그 위에 적을 수 있고,
콘텐츠가 있어야 에디터가 무엇을 편집해야 하는지 정해진다.

| 마일스톤 | 내용 | 산출물 |
|---|---|---|
| 1. 이벤트 커맨드 | 데이터 커맨드 목록과 실행기, 검증기, Lua 탈출구 | `scripts/rpg/commands.lua`, 단위 테스트 |
| 2. 기획서대로 재작업 | 항구 마을과 여관 맵, 오브젝트, 대사, PC/모바일 UI 배치 | 새 맵과 이벤트 정의, 모바일 조작 버튼, 장소 이름 표시 |

## 3. 이벤트 커맨드 설계 (마일스톤 1)

### 3.1 원칙

1. **데이터가 먼저, Lua는 탈출구.** 이벤트 하나는 커맨드의 목록이다. 목록은 순수 데이터라
   JSON으로 오갈 수 있고, 에디터가 만들고 읽을 수 있다. 커맨드로 적기 어려운 것(전투,
   미니게임)은 `script` 커맨드로 등록된 Lua 함수를 부른다.
2. **실행기는 바꾸지 않는다.** 6단계의 `interpreter.lua`는 "스크립트 함수를 코루틴으로
   돌리고 조작을 잠근다"만 안다. 커맨드 목록은 그 함수를 만들어 주는 층
   (`commands.lua`)이며, 실행기는 커맨드의 존재를 모른다. 기존 `script` 이벤트도 그대로 돈다.
3. **분기는 중첩이지 점프가 아니다.** RPG Maker는 평탄한 목록과 들여쓰기로 분기를
   표현하지만, JSON과 웹 에디터에는 중첩 배열이 훨씬 다루기 쉽고 라벨 관리가 필요 없다.
4. **모르는 커맨드는 로드할 때 실패한다.** 실행 도중이 아니라 맵을 열 때 어디가 틀렸는지
   경로(`events[2].commands[3].branches[1][2]`)와 함께 알린다.

### 3.2 커맨드 목록 (v1)

| code | 인자 | 하는 일 | 기다리는가 |
|---|---|---|---|
| `message` | `text`, `name`, `face` | 대화창 | 닫힐 때까지 |
| `choice` | `options`, `cancel`, `branches` | 선택지, 고른 번호의 목록을 이어서 실행 | 고를 때까지 |
| `wait` | `ms` | 멈춤 | 그만큼 |
| `transfer` | `map`, `x`, `y`, `dir` | 맵 이동 (이 뒤의 커맨드는 실행되지 않는다) | — |
| `moveRoute` | `target`, `route`, `wait` | 이동 루트 | `wait`이 거짓이 아니면 끝날 때까지 |
| `turn` | `target`, `dir` | 방향만 돌린다 | 아니오 |
| `setFlag` | `key`, `value` | `ctx.state[key] = value` | 아니오 |
| `setVar` | `key`, `op`, `value` | `op`는 `=`, `+`, `-` | 아니오 |
| `if` | `cond`, `thenDo`, `elseDo` | 조건 분기 | 안쪽에 따라 |
| `playSe` | `file`, `id` | 효과음 | 아니오 |
| `playBgm` | `file`, `volume`, `fade` | 배경음 (같은 곡이면 이어서) | 아니오 |
| `showLocation` | `text`, `seconds` | 장소 이름 표시 (씬이 그린다) | 아니오 |
| `scene` | `name`, `fade` | 다른 씬으로 (에필로그 뒤 타이틀) | — |
| `script` | `name`, `args` 또는 `run` | 등록된 Lua 함수 (탈출구) | 함수가 정하는 대로 |
| `comment` | `text` | 아무것도 하지 않는다 (에디터 가독성) | 아니오 |

조건(`cond`)의 형태는 둘뿐이다.

```lua
	{ flag = "heardAltar" }                      -- 참인가
	{ flag = "booked", equals = false }          -- 값 비교
	{ var = "silver", op = ">=", value = 2 }     -- 수 비교
```

`then`과 `else`는 Lua 예약어라 키로 쓸 수 없다. `thenDo`, `elseDo`로 적는다 —
JSON에서도 같은 이름을 쓴다.

### 3.3 적는 모양

```lua
	{
		id = "innkeeper",
		x = 10, y = 4, dir = "down",
		charset = { file = CHARSET, index = 3 },
		trigger = "action",
		commands = {
			{ code = "message", name = "여관 주인", face = { file = FACES, index = 3 },
			  text = "어서 오세요. 저녁 배를 기다리는 분이시군요." },
			{ code = "choice", options = { "묵는다", "배를 탄다", "그냥 둘러본다" }, cancel = 3,
			  branches = {
				{ { code = "setFlag", key = "booked", value = true },
				  { code = "message", name = "여관 주인", text = "그럼 짐을 올려 두세요." } },
				{ { code = "message", name = "여관 주인", text = "다들 처음엔 그렇게 말하죠." } },
				{ { code = "message", name = "여관 주인", text = "난로 옆이 제일 따뜻합니다." } },
			  } },
		},
	}
```

같은 이벤트를 JSON으로 옮기면 그대로 배열과 객체가 된다 — 마일스톤 3에서 에디터가
읽고 쓸 형태다. `script = function(self, ctx) ... end`는 계속 동작하며, 커맨드로 적기
어려운 이벤트는 그쪽에 남긴다.

### 3.4 구현 메모

- `Commands.compile(list)` → `function(self, ctx)`. 실행기에는 지금과 같은 함수 하나로 들어간다.
- `Commands.validate(list)` → `ok, errors`. 맵 정의를 읽을 때 부르고, 실패하면 씬이
  기존 `sceneError`와 같은 경로로 화면에 알린다.
- `showLocation`과 `scene`은 `ctx.host`를 통해 씬에 위임한다 (6단계의 `transfer`와 같은 방식).
  프레임워크가 씬의 화면 구성을 알지 않게 한다.
- `script` 커맨드의 `name`은 맵 정의 파일이 등록한다: `scripts = { harborStorm = function(...) end }`.
  이름으로 부르므로 JSON에 실려도 왕복이 깨지지 않는다.

## 6. 위험과 미리 정해 둔 것

1. **맵을 누가 그리는가.** 기획서는 타일 좌표까지 정해 두었으므로, 에디터로 그리든
   생성기로 만들든 결과가 같아야 한다. 마일스톤 2에서는 **결정적 생성기**(난수 없음)로
   만들고, 마일스톤 3에서 에디터 왕복을 확인한다. 손으로 그린 맵이 더 좋아 보이면
   그때 갈아 끼운다 — 좌표가 문서에 있으므로 어느 쪽이든 되돌릴 수 있다.
2. **커맨드가 늘어나는 것.** v1은 15종으로 못 박는다. 기획서의 이벤트를 전부 적을 수 있는
   최소 집합이며, 새 커맨드는 "그것 없이는 적을 수 없는 이벤트"가 나올 때만 더한다.
3. **8단계 데모를 버리는가.** 버리지 않는다. `village.json`과 `room.json`은 타일맵과
   이벤트의 회귀 테스트가 계속 쓰고, 새 데모는 항구 마을로 따로 선다. 메뉴에 남는 것은
   새 데모 하나다.
4. **기획서의 결정 세 가지**(제목, `inn.ogg` 커밋 여부, 에필로그 문구)는 저자 몫이며,
   정해지기 전에는 각각 권장안으로 진행하고 문서에 표시해 둔다.

## 7. 의존 관계

- 선행: 8단계 (씬 구조와 대화창), 6단계 (실행기와 `ctx`)
- 후속: 저장과 로드(`ctx.state` 직렬화), 에디터의 이벤트 편집
