# 1단계: 엔진 코어 보강 (범용)

**권장 모델**: Claude Opus 5 — 설계 결정이 이 문서에 이미 내려져 있고 작업이 체크리스트 단위로 좁게 쪼개져 있어, 로드맵의 최소 기준선인 Opus 5로 진행한다.

> 목표: RPG든 플래피버드든 어떤 장르에서나 필요한 범용 기능의 빈 곳과, 조사에서 드러난 코어 버그를 메운다.
> RPG 전용 개념은 이 단계에 하나도 들어가지 않는다.

## 왜 필요한가

2026-08-15 조사에서 확인된 사실 기준으로, 다음이 뒤 단계들을 막고 있다.

- 텍스트 폭 측정이 Lua에 노출되지 않아 가운데 정렬, 자동 줄바꿈이 불가능하다 (`scripts/scenes/menu.lua:19`가 반폭을 하드코딩으로 우회 중). 대화창(7단계)의 선행 조건이다.
- jsoncpp가 이미 링크되어 있지만 Lua에서 JSON을 읽을 방법이 없다. 맵 로딩(2단계)과 각종 데이터 파일의 선행 조건이다.
- 스프라이트 시트 분할이 4x4로 하드코딩되어 있다 (`src/Constants.h:99-102`). R2K3 CharSet은 3x4라 반드시 풀어야 한다.
- 논리 해상도가 768x896(플래피버드 세로 화면)으로 하드코딩되어 있다 (`src/platform/sdl2/AppSDL2.cpp:139`). 범용 엔진이라면 게임이 해상도를 정해야 한다.
- 자잘하지만 실제로 물리는 버그들이 있다.

## 작업 항목

### A. Lua API 확장 (모두 범용)

- [x] `GetTextWidth(text)` 바인딩 추가 (2026-08-15, Lua 테스트 12건)
- [x] `Json.Load(path)` → Lua 테이블 변환 바인딩 (`src/lua_json.cpp`, 실패 시 nil + 오류 메시지, Lua 테스트 17건)
- [x] `Sprite.SetSheetGrid(handle, cols, rows)` 추가, 기본 4x4 유지. 겸사겸사 `setRect`의 행 계산이 행 수로 나누던 잠복 버그(4x4에서만 우연히 동작)도 수정
- [x] `Sprite.Dispose(handle)` 추가. `Sprite.GetRect`의 lua_settable 인덱스 오류(호출 즉시 런타임 오류)도 발견해 수정
- [x] 화면 설정을 게임이 정하게 한다 — 프로젝트 루트의 `game.json`(`windowWidth`, `windowHeight`)에서 읽고, `INITIAL2D_WINDOW=WxH` 환경 변수가 우선한다 (개발과 테스트용). 파일이 없으면 기존 기본값 768x896 유지. `config.setting`은 엔진이 쓰는 출력 파일이라 쓰지 않기로 결정.

### B. 버그 수정

- [x] 글리프 테이블 크기 `[55203]` → `[0xD7A4]` 수정. 추가 발견: ParseFont가 fnt의 id를 경계 검사 없이 쓰던 문제, drawText가 빈 문자열에서 빈 벡터 max_element를 역참조하던 UB도 수정. (`Charset` 구조의 4.4MB 메모리 최적화는 보류 — 동작 문제가 아님)
- [x] `Font::open()`의 반전된 guard 수정 (첫 호출이 파싱을 건너뛰던 문제)
- [x] `src/Tilemap.cpp`의 백슬래시 경로 문제 — 2단계 재작성에서 해결 (모든 경로가 `NormalizePath`를 거친다)
- [x] `Rectangle.h`의 `operator=` return 누락 수정 (연쇄 대입 회귀 테스트 포함)
- [x] 오디오 루프 플래그 정리 — 원인은 반전이 아니라 `lua_toboolean` 뒤 `0이면 -1` 변환이었고, Lua에서는 숫자 0도 참이라 사실상 false만 무한 반복이 되는 구조였다. 새 계약: 불리언 true = 무한, false = 1회, 숫자 = SDL_mixer 원시 루프 값. flappy와 menu의 효과음은 "절반 길이 파일을 2회 재생"하던 기존 소리를 보존하기 위해 숫자 1로 변경. `PlayMusic`, `PlaySound`, `InsertNextMusic` 모두 적용.

### C. 결정 사항 (구현 전에 확정)

- **z순서는 코어에 넣지 않는다.** 그리기 순서는 지금처럼 Lua `Render()`의 호출 순서로 제어한다. RPG의 y정렬은 5단계에서 Lua 테이블 정렬로 해결한다. 수백 스프라이트 수준에서는 성능 문제가 없고, 코어를 단순하게 유지한다.
- **카메라도 코어에 넣지 않는다.** 일반 스프라이트는 Lua에서 카메라 오프셋을 빼서 그리고, 타일맵만 C++ 렌더러가 오프셋 인자를 받는다 (2단계).
