# 5단계: RPG 프레임워크 1 — 캐릭터 렌더링과 이동

**권장 모델**: Claude Opus 5 — 명세가 상세한 Lua 구현이며, 이동의 손맛 같은 짧은 조정을 여러 번 반복하는 작업이다. 로드맵의 최소 기준선인 Opus 5로 진행한다.

> 목표: CharSet 캐릭터가 타일맵 위를 걸어다닌다. 4방향 걷기 애니메이션, 그리드 이동, 충돌, 카메라 추적까지.
> 여기서부터 RPG 프레임워크 레이어다. **전부 Lua**(`scripts/rpg/`)로 작성하며 C++ 수정은 원칙적으로 없다.

## 구조

```
scripts/rpg/
  specs.lua       -- 리소스 규격 데이터 (4단계)
  character.lua   -- 맵 위의 움직이는 객체 (플레이어와 NPC 공용)
  player.lua      -- 입력을 character에 연결
  camera.lua      -- 대상 추적, 맵 경계 클램프
  map_scene.lua   -- 타일맵 + 캐릭터들 + 카메라를 묶는 씬
```

## 핵심 설계

### character.lua

플레이어와 NPC가 같은 클래스를 쓴다. 상태는 단순하게 유지한다.

- 위치는 **타일 좌표**(`tx, ty`)가 진실이고, 픽셀 좌표는 이동 보간 중에만 어긋난다. R2K3와 같은 그리드 이동 방식.
- `moveTo(dir)`: 목표 타일이 통행 가능하면(`Tilemap.IsPassable` + 다른 캐릭터 점유 검사) 보간 이동 시작. 이동 중에는 새 입력을 큐에 하나만 보관.
- 걷기 애니메이션: CharSet 프레임 3장을 `왼발, 중립, 오른발` 순으로 재생하되 실제 걸음 패턴은 `중립, 왼발, 중립, 오른발` 반복. `Sprite.SetSheetGrid`(1단계)와 `SetRect`로 시트에서 잘라 쓴다. 시트 안의 캐릭터 인덱스(0~7)와 방향 행 매핑은 `specs.lua` 데이터를 따른다.
- 방향 전환: 정지 상태에서 다른 방향키를 짧게 누르면 이동 없이 방향만 바꾸는 R2K3식 처리(선택 사항이지만 손맛에 크게 기여).

### 그리기 순서

- 타일맵 하층 → 캐릭터들(y좌표 오름차순 정렬) → 타일맵 상층 순으로 그린다. 2단계의 `Tilemap.Draw(handle, layerFrom, layerTo, camX, camY)` 레이어 분할이 이를 위한 것이다.
- y정렬은 Lua 테이블 `table.sort` 한 줄이면 된다. 코어에 z순서를 넣지 않기로 한 결정(1단계)이 여기서 검증된다.

### camera.lua

- 대상(플레이어)의 픽셀 좌표를 따라가되 맵 경계에서 멈춘다 (맵이 화면보다 작으면 가운데 정렬).
- 카메라는 값(오프셋)일 뿐이며, 모든 그리기 호출에 빼서 전달한다.

## 작업 항목

- [x] `map_scene.lua`: 맵 로드, 캐릭터 등록, y정렬 그리기, 갱신 루프

## 구현 노트 (2026-08-16)

- **좌표 규약**: 타일 좌표 `tx, ty`가 진실이고, 이동을 시작하는 순간 목적지 칸으로 바뀐다. `offsetX/Y`가 도착할 때까지 그 차이를 메운다 (R2K3와 같은 방식). 덕분에 "이동 중인 캐릭터가 목적지 칸을 점유한다"가 공짜로 성립해, 두 캐릭터가 같은 칸으로 동시에 들어오지 못한다.
- **주입 구조**: `character`, `player`, `camera`, `rng`는 엔진 전역을 하나도 부르지 않는다. 통행 판정은 `canPass(tx, ty, who)` 함수를, 입력은 Input과 같은 표면의 테이블을 주입받는다. 전역에 닿는 유일한 층이 `map_scene.lua`다. 이 규칙 덕분에 이동 규칙 전체가 헤드리스로 검증된다 ([09-testing.md](09-testing.md) 3.2절).
- **남은 진행분(carry) 이어 붙이기**: 한 프레임에 칸 경계를 넘으면 초과분을 다음 칸의 진행도로 넘긴다. 버리면 칸마다 최대 한 프레임어치가 사라져 경계에서 미세하게 걸린다.
- **플레이스홀더 CharSet**: RTP 변환 결과는 커밋 금지라(4단계) 데모와 골든이 신선한 체크아웃에서 돌지 않는다. 같은 규격(288x256, 8명)의 대체 시트를 `tools/generate_charset.py`로 만들어 `resources/charsets/placeholder.png`로 커밋했다. 정품 보유자는 `INITIAL2D_CHARSET`으로 진짜 시트를 쓸 수 있다.
- **골든 씬의 상태 고정**: `rpg_walk_scene.lua`는 캐릭터를 Initialize에서 원하는 자세(반 칸 이동 중 포함)로 세워 두고 Update에서는 `dt = 0`으로 스프라이트 동기화만 한다. 고정 스텝 루프에서 Update 횟수는 스크린샷 프레임과 어긋나므로 시간에 따라 변하는 화면은 골든으로 찍을 수 없다 ([09-testing.md](09-testing.md) 4절).
- **메뉴 라벨 폭**: 버튼 라벨을 손으로 준 근사값 대신 `GetTextWidth`(1단계 산출물)로 재게 바꿨다. 1단계에서 만든 API가 실제로 쓰이는 첫 자리다.
- **알려진 한계 — 확대**: 타일이 16px이라 768x896 논리 해상도에서는 캐릭터가 작게 보인다. 확대는 `Tilemap.Draw`와 스프라이트에 공통 배율이 필요한 렌더러 차원의 이야기라 이 단계 범위 밖이다. 당장은 `game.json`의 해상도를 낮춰(예: 384x448) 게임별로 조절한다.
