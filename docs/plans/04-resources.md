# 4단계: 리소스 파이프라인 — R2K3 리소스 어댑터

**권장 모델**: Claude Opus 5 — 규격이 이미 조사로 확정된 변환 스크립트와 데이터 작성 위주라, 로드맵의 최소 기준선인 Opus 5로 진행한다.

> 목표: `resources/RTP.zip`(RPG Maker 2003 RTP, 2023년 재배포판)을 엔진이 바로 쓸 수 있는 형태로 변환하는 도구를 만들고, 리소스 규격을 Lua 데이터로 기술한다.
> 원칙: R2K3 규격은 엔진의 규격이 아니다. 엔진(C++)은 PNG와 OGG만 알고, "CharSet은 288x256이고 한 캐릭터는 3x4 프레임"이라는 지식은 전부 Lua 쪽 데이터에 둔다.

## 라이선스 (가장 먼저 확인할 것)

- RPG Maker의 개정 EULA에 따라 RTP 소재는 **해당 RPG Maker 제품(여기서는 RPG Maker 2003)의 정품 보유자에 한해** 다른 엔진의 게임에도 사용할 수 있다. 배포 전에 최신 약관 원문을 다시 확인한다.
- 소재 자체의 재배포는 금지다. **RTP.zip과 변환 결과물은 git에 커밋하지 않는다** (`resources/.gitignore`가 이미 `RTP.zip`을 제외하고 있음을 2026-08-15 확인. 변환 결과 폴더도 제외 목록에 추가할 것).
- 저장소에 포함할 데모용 소재가 필요하면 공개 라이선스 타일셋(InitialEditor가 이미 쓰는 FSM, Tuxemon 계열)을 쓴다. RTP는 "정품 보유자의 로컬 개발용" 경로로 취급한다.

## 조사로 확인된 RTP 규격 (2026-08-15 조사, 2026-08-16 구현 시 실측 정정)

| 리소스 | 파일 수 | 규격 | 비고 |
|---|---|---|---|

| ChipSet | 5 | 480x256 | 16x16 타일 30열 16행, 왼쪽 일부는 오토타일 영역 |
| FaceSet | 5 | 192x192 | 48x48 얼굴 16개 (4x4) |
| System | 4 | 160x80 | 대화창 스킨: 배경, 프레임, 커서, 화살표, 숫자, 글자색 팔레트 |
| System2 | 3 | **80x96** | 전투 UI 스킨 (조사 시 160x80으로 적었던 것을 정정) |
| Title | 4 | 320x240 | 원본 게임 해상도가 320x240 기준 |
| Backdrop | 34 | 320x240 | 전투 배경 |
| GameOver | 1 | 320x240 | |
| Panorama | 13 | 640x480 또는 320x240 | 원경 스크롤용 |
| Monster | 115 | 다양 (44x84 ~ 195x158) | |
| Battle 계열 | 54 + 64 + 1 | 다양 | Battle(애니메이션), BattleCharSet(144x384), BattleWeapon(192x512) |
| Music | 141 MIDI + 10 WAV | MIDI는 그대로 재생 불가 | 조사 때 152개 전부 MIDI로 적었으나 WAV가 10개 섞여 있다 |
| Sound | 206 | WAV | SDL2_mixer로 바로 재생 가능 |

조사 때의 파일 수가 하나씩 많았던 것은 zip의 디렉터리 항목까지 세었기 때문이다.
빈 디렉터리(Battle2, Frame, Movie, Picture)도 아카이브에 들어 있다.

주의할 함정 두 가지:

1. **투명색.** 이 PNG들은 8비트 팔레트인데 tRNS(투명) 청크가 파일마다 들쭉날쭉이다 (ChipSet에는 있고 CharSet과 System에는 없음). R2K3 관례는 "팔레트 0번 = 투명"이므로, **변환 단계에서 tRNS 유무와 무관하게 팔레트 0번을 알파 0으로 강제 변환**해야 한다. 엔진 로더를 고치는 것보다 사전 변환이 깔끔하다.
   단, **전부 뚫으면 안 된다** (2026-08-16 실측). 팔레트 0번의 사용 비율과 테두리 점유율을 재 보면 두 부류가 갈린다.
   - 키 컬러 부류: CharSet(초록 32,156,0) 65%, ChipSet(마젠타) 12%, Monster(파랑) 46%, Battle 계열(하늘색) 80~99%, System 20~35%. 전부 이미지 테두리를 100% 가깝게 두른다 → 뚫는다.
   - 배경 그림 부류: Backdrop 0%, Title 0.5%, GameOver 1.6%, Panorama는 파일에 따라 86%가 실제 하늘색이다 → 뚫으면 그림에 구멍이 난다.
   - FaceSet은 5장 모두 0번을 한 픽셀도 쓰지 않아 어느 쪽이든 결과가 같다. 관례를 따라 투명 카테고리로 둔다.
2. **해상도.** 원본이 320x240 기준이므로 그대로 그리면 요즘 화면에서 아주 작다. RPG 데모는 논리 해상도 320x240에 창 배율 2배나 3배(정수배)로 표시하는 것을 기본으로 한다 (1단계의 해상도 설정 기능 사용).

## 작업 항목

- [x] 변환 도구 `tools/rtp_import.py` 작성 (2026-08-16):
  - zip에서 바로 읽어 `resources/rtp/`로 변환한다 (원본을 통째로 푸는 중간 단계를 두지 않는다)
  - 팔레트 0번을 알파 0으로 만들어 32비트 RGBA PNG로 저장. 카테고리별 투명 정책은 `CATEGORIES` 표에 근거와 함께 둔다
  - 투명 픽셀의 RGB는 0으로 지운다 (키 컬러를 남기면 확대할 때 가장자리에 번진다)
  - WAV는 복사, `--ogg`로 OGG 변환 (ffmpeg)
  - 파일명의 공백은 그대로 둔다 — 엔진 로더가 공백 경로를 읽는 것을 실측으로 확인했다. `--normalize-names`로 언더스코어 변환도 가능
  - `--only`로 일부만 다시 변환할 때 매니페스트의 나머지 카테고리 기록은 보존한다
- [x] MIDI 처리 방침 결정과 구현 (2026-08-16): **1안과 2안을 함께 채택**했다.
  - 기본값은 2안이다. MIDI 141개는 변환하지 않고 건너뛰며, 데모의 음악은 자작곡(`resources/audio/`)을 쓴다. 저작권이 깔끔하고 변환 품질에 좌우되지 않는다.
  - 원하면 1안을 쓴다: `--soundfont <sf2>`를 주면 fluidsynth로 렌더링하고 ffmpeg으로 OGG를 만든다. 엔진에는 MIDI 재생기를 넣지 않는다는 방침은 그대로다.
  - 동작 확인은 macOS가 갖고 있는 `gs_instruments.dls`로 했다 (fluidsynth 2.4.0이 DLS를 읽는다). 48초짜리 OGG가 정상적으로 나온다. 배포용 음원은 자유 라이선스 사운드폰트로 만들어야 한다.
- [x] 규격 데이터 `scripts/rpg/specs.lua` 작성 (2026-08-16) — 엔진이 아니라 Lua가 아는 지식:
  ```lua
  return {
    charset = { sheetW = 288, sheetH = 256, perSheet = 8, blockW = 72, blockH = 128,
                frameW = 24, frameH = 32, frames = 3,
                dirRows = { up = 0, right = 1, down = 2, left = 3 } },  -- 구현 시 실물로 검증할 것
    faceset = { size = 48, cols = 4, rows = 4 },
    chipset = { tile = 16, columns = 30 },
    window  = { skinW = 160, skinH = 80 },  -- 세부 분할은 7단계에서 확정
  }
  ```
  방향 행 순서와 System 분할 좌표는 문서 기억에 의존하지 말고 **실제 이미지를 열어 확인한 뒤 확정**한다 (EasyRPG Player 소스가 좋은 교차 검증 자료다).

  실제로 확정한 값 (Actor1.png와 System.png를 확대해 눈으로 확인, 2026-08-16):
  - 방향 행은 위(0), 오른쪽(1), 아래(2), 왼쪽(3)이 맞다. 0행은 뒤통수, 1행은 오른쪽 옆모습(눈이 오른쪽), 3행은 그 반대다.
  - 걷기 열은 왼발, 서기, 오른발이고 가운데가 서 있는 자세라 `0, 1, 2, 1` 순서로 돈다.
  - System은 창 바탕(0,0,32,32), 테두리(32,0,32,32, 모서리 8px), 커서 둘(64,0), (96,0), 화살표(128,0,32,32), 타이머 숫자 "0123456789:" 8x16씩 (32,32)부터, 글자색 견본 16x16짜리 20개가 (0,48)부터 10열 2행이다. 세부 확정은 7단계에서 한다.
  - 시트 전체를 24x32 격자로 보면 12열 8행이라 `Sprite.SetSheetGrid(12, 8)`에 그대로 넣을 수 있다. `charsetFrameIndex()`가 그 프레임 번호를 준다.
