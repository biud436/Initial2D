# 8단계: 통합 데모 — 작은 마을

**권장 모델**: Claude Opus 5 — 콘텐츠 제작과 통합 테스트가 중심이다. 다만 통합 디버깅에서 원인이 여러 단계에 걸쳐 있는 문제가 나오면 Fable 5로 승격한다.

> 목표: 1부터 7단계의 결과물을 전부 사용하는 작은 데모 게임을 만든다. 이 데모가 곧 로드맵 전체의 인수 테스트다.
> 완성 후에는 기존 메뉴 씬(`scripts/scenes/menu.lua`)에서 플래피버드와 나란히 선택할 수 있게 한다 — "같은 엔진에서 두 장르"가 범용성의 증명이다.

## 데모 내용

- **타이틀 화면**: 배경 이미지, 커서 메뉴(시작, 종료). 7단계의 window와 choice를 재사용.
- **마을 맵**: InitialEditor로 제작한 맵 (3단계 워크플로우의 실전 검증). ChipSet 기반, 2개 층 이상, 통행 데이터 포함.
- **NPC 3명**: 말을 걸면 대화 (한 명은 얼굴과 선택지 포함, 한 명은 배회, 한 명은 고정).
- **집 1채**: 문으로 실내 맵 전환과 복귀 (페이드).
- **BGM과 효과음**: 자작곡 사용 (RTP MIDI 변환에 의존하지 않음, 4단계의 결정 참고).
- **자동 플레이 테스트**: 기존 `AUTOPLAY` 방식으로 "말 걸기 → 선택 → 맵 이동"을 스크립트로 재생해 CI 스크린샷 검증에 넣는다.

## 계획과 달라진 것

1. **맵은 에디터로 새로 그리지 않고 6단계의 것을 썼다.** `village.json`과 `room.json`은 이미 맵 포맷 v1이고 통행 데이터를 갖고 있으며, 에디터 왕복(열기, 저장, 내보내기)은 3단계에서 실제 조작으로 확인했다. 데모를 위해 같은 검증을 반복하는 대신 콘텐츠를 늘리는 데 시간을 썼다.
2. **이벤트 정의 파일은 `scripts/maps/`에 남겼다.** 계획은 `scripts/games/rpgdemo/` 아래로 모으는 것이었지만, "맵 파일과 짝이 되는 정의 파일"은 데모의 사정이 아니라 프레임워크의 규약이고 README와 6단계 문서가 그렇게 쓰고 있다. 데모 폴더에는 씬만 두었다.
3. **타이틀 메뉴 항목은 "시작, 종료"가 아니라 "시작, 조작 방법, 나가기"다.** 데모가 미니 게임 허브 안에서 돌기 때문에 종료가 아니라 목록으로 돌아가는 것이 맞고, 조작 방법 항목이 대화창(7단계)을 타이틀에서도 쓰는 자리가 된다.
4. **NPC 셋은 촌장(얼굴과 선택지), 아이(배회), 상인(고정)이다.** 상인에게 받은 약초는 `ctx.state`에 남아 아이와 오두막 주민의 대사를 바꾼다 — 맵을 넘는 상태 공유를 데모에서 실제로 보인다. 순찰병(병렬 이벤트)과 잠긴 문은 6단계에서 이어졌다.
5. **BGM은 곡을 새로 만들지 않고 슬롯을 만들었다.** 맵 정의의 `bgm` 필드와 `scripts/bgm.lua`(같은 곡이면 다시 틀지 않는다)로 곡을 갈아 끼울 수 있게 하고, 데모에는 저자의 자작곡 `bless.ogg`를 건다. 문 여닫는 효과음은 코드로 합성해 커밋했다 (`tools/generate_ui_assets.py`).

## v2 후보 (이번 로드맵에서 의도적으로 제외한 것)

이번 로드맵의 목표는 "가능함의 증명"이지 R2K3 전체 재현이 아니다. 다음은 데모 이후 필요해질 때 계획한다.

- 오토타일 (에디터와 엔진 양쪽)
- 저장과 로드 (`ctx.state` 직렬화, SQLite가 이미 링크되어 있으므로 후보)
- 메뉴 화면 (아이템, 상태), 데이터베이스(액터, 아이템)
- 전투 시스템
- 날씨, 화면 효과, 픽처
- 씬 스택 (현재 단일 씬 교체 구조의 한계가 실제로 드러나는 시점에)
