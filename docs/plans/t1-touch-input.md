# T1: 모바일 터치 조작 (멀티터치와 화면 크기 대응)

> 단계 번호 대신 T를 쓴다. 로드맵 v2가 예약한 12~14단계(저장, 오토타일, 씬 스택)와
> 부딪히지 않게 하는 A-트랙과 같은 규칙이다.

> 작성일: 2026-08-24. 알데바란(횡스크롤)을 실기(Galaxy S24)에서 조작할 수 있게,
> 가상 조이스틱과 액션 버튼을 화면 크기에 맞추는 단계다.

**권장 모델**: Fable 5. 엔진 입력 API(멀티터치)와 UI 레이어와 게임 씬 세 층을 함께
바꾸며, 기존 인수 시나리오(마우스 = 첫 손가락)를 깨지 않는 하위 호환 설계가 필요하다.

## 1. 문제

2026-08-24 기준 터치 조작에는 세 가지 문제가 있다.

1. **단일 터치.** vpad와 buttons가 엔진의 마우스 API(SDL이 첫 손가락을 마우스로
   매핑)를 쓴다. 손가락 하나만 인식되므로 패드로 달리면서 점프 버튼을 누를 수
   없다. 횡스크롤 액션에서는 치명적이다. (A1에서 "단일 터치용 관성 규칙"으로
   우회했지만 근본 해결이 아니다.)
2. **고정 크기.** 버튼 크기가 논리 픽셀 상수라 기기마다 물리 크기가 다르다.
   S24에서 pause 버튼(26px)은 약 24dp로, Android 권장 최소 터치 목표(48dp)의
   절반이다.
3. **D-패드의 손맛.** 손가락이 패드 원 밖으로 미끄러지면 입력이 끊긴다.
   조이스틱처럼 "잡고 끄는" 동작이 안 된다.

배경: Android에서는 논리 높이가 고정(896/배율)이고 가로만 화면 비율대로
확장된다 (`AppSDL2.cpp`). 그래서 "높이에 비례하는 크기"는 곧 "화면에 비례하는
물리 크기"다. DPI 조회 없이도 비례 배치로 기기 대응이 된다.

## 2. 설계

### 2.1 엔진: 멀티터치 API (C++, SDL2 어댑터만)

"이 기능이 플래피버드에도 말이 되는가?" — 터치 입력은 장르 중립이므로 코어에 넣는다.

- `Input`에 손가락별 상태 배열을 둔다. 마우스와 같은 4-상태 기계와 이벤트
  래치(폴링 사이의 짧은 탭 보존)를 손가락마다 적용한다.
- `AppSDL2::HandleEvent`가 `SDL_FINGERDOWN/MOTION/UP`을 받아 창 좌표를 논리
  좌표로 바꿔(`SDL_RenderWindowToLogical`) `Input`에 넘긴다.
- Lua 표면: `Input.GetTouchCount()`, `Input.GetTouch(i)` (id, x, y, phase를
  돌려준다. phase는 "down", "press", "up"). Windows GDI 경로는 건드리지 않는다
  (`#ifndef RS_WINDOWS` 가드, 래치와 같은 방식).

### 2.2 UI: 포인터 통합과 비례 배치 (Lua)

- `scripts/ui/touch.lua` (신설): 터치 API가 있으면 터치를, 없으면 마우스를
  포인터 목록 하나로 합쳐 준다. SDL이 첫 손가락을 마우스로도 흉내내므로 같은
  손가락이 두 번 보일 수 있는데, 방향과 버튼 판정은 합집합이라 무해하다.
  기존 테스트의 가짜 Input(터치 API 없음)은 자동으로 마우스 폴백을 탄다.
- `scripts/ui/layout.lua` (신설): 순수 함수로 화면 크기(W, H)에서 컨트롤
  배치를 계산한다. 크기는 H에 비례(패드 30%, 주 버튼 15%, 보조 11%, 시스템 10%,
  여백 3%), 위치는 모서리 앵커. 어느 W(데스크톱 384부터 S24의 970까지)에서도
  패드와 버튼 무리가 겹치지 않는 것을 단위 테스트로 못 박는다.
- `scripts/ui/vpad.lua`: 손가락 소유권 방식 조이스틱으로. 패드 안에서 눌린
  포인터를 잡고, 잡힌 동안에는 원 밖으로 나가도 방향을 유지한다(반경 무한,
  데드존만 적용). 놓으면 풀린다. `direction` 순수 함수와 기존 API는 유지.
- `scripts/ui/buttons.lua`: 모든 포인터로 판정. 히트 슬롭(판정 반경 1.25배)을
  더하되, 슬롭끼리 겹치면 중심이 가까운 버튼 하나만 먹는다(winner take all).

### 2.3 게임: 알데바란 적용

- `game.lua`의 고정 좌표 배치를 `layout.lua` 호출로 바꾼다.
- `status()`에 컨트롤 배치를 노출해, 인수 시나리오가 좌표를 하드코딩하지 않고
  계산된 중심을 누르게 한다.

## 3. 검증

- Lua 단위: layout 순수 함수(여러 해상도에서 경계와 겹침), vpad 소유권(잡기,
  끌기, 놓기, 두 번째 손가락 무시), buttons 다중 포인터(동시 두 버튼, 슬롭
  겹침의 승자). 재생기(`input_replay.lua`)에 터치 시퀀스를 추가한다.
- 인수 시나리오(stop=touch): 기존 다섯 검증(걷기, 점프, 공격, 정지, 계속)을
  계산된 좌표로 유지하고, **"패드로 걸으면서 점프"** 동시 입력 검증을 더한다.
- 골든: 첫 화면 골든에 터치 UI는 없다(INITIAL2D_VPAD 없이 캡처). 영향 없음.
- 실기: APK를 S24에 설치해 실행하고, 스크린샷으로 배치(모서리 앵커, 크기)를
  확인한다. 손맛(패드 감도, 버튼 간격)은 사용자 몫으로 남긴다.
