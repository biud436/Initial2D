# 알데바란 1단계: 코어 (숲을 달리고 뛰어다닌다)

> 기획서: [docs/design/aldebaran.md](../design/aldebaran.md).
> 알데바란 트랙은 roadmap-v2의 후보였던 "전투 (장르를 넓히고 싶다)"가
> 저자의 기획서 반입(2026-08-23)으로 앞당겨진 것이다. 문서 번호 대신 이름을 쓴다.
> 기존 로드맵의 12~14단계 번호(저장, 오토타일, 씬 스택)와 부딪히지 않기 위해서다.

**권장 모델**: Fable 5. 새 장르의 토대다. 물리와 충돌의 구조, 플레이어 상태 기계,
시트 규격이 다음 두 단계(전투, 콘텐츠)의 토대가 된다.

> 목표: **카르토가 검은 안개의 숲을 달리고, 대쉬하고, 두 번 뛰어오른다.**
> 아직 때릴 것은 없다. 그것은 [2단계](aldebaran-2-combat.md)다.

## 1. 원칙

1. **C++ 무수정.** 횡스크롤 물리도 충돌도 전부 `scripts/games/aldebaran/` Lua다.
   엔진에는 이미 필요한 것이 다 있다: 스프라이트 시트, 타일맵과 `IsPassable`,
   카메라 오프셋 인자, 렌더 배율.
2. **RPG 레이어를 쓰지 않는다.** `scripts/rpg/`는 그리드 이동과 이벤트의 세계다.
   이 게임은 픽셀 단위 물리라 그 위에 얹을 것이 없다. 다만 **장르 중립 부품**은
   그대로 쓴다: `window.lua`와 `choice.lua`(창과 메뉴), `rng.lua`(시드 난수),
   `vpad.lua`와 `buttons.lua`(터치), `bgm.lua`.
3. **로직은 순수 모듈로.** 플레이어 컨트롤러는 엔진에 닿지 않는 표와 함수로 만들고
   (`player.lua`), 씬이 입력과 충돌 조회 함수를 주입한다. 단위 테스트는 가짜 충돌
   지도를 넣어 물리를 프레임 단위로 재현한다.
4. **도트는 단색 스케치 위에 디더링 명암, 명확한 테두리** (2026-08-23 이미지 지침).
   생성기의 그리기 순서가 그 지침 그대로다: 실루엣을 단색으로 채우고, 밝은 색과
   어두운 색을 체커보드 디더로 얹고, 마지막에 어두운 아웃라인을 두른다.

## 2. 마일스톤

| 마일스톤 | 내용 | 산출물 |
|---|---|---|
| 1. 자산 | 타일셋, 카르토 시트, 배경, 타이틀 그림, 효과음 생성기 | `tools/generate_aldebaran_assets.py`, `resources/aldebaran/` |
| 2. 스테이지 맵 | 검은 안개의 숲 128x28, 손으로 정한 지형 | `tools/generate_aldebaran_maps.py`, `resources/maps/aldebaran_forest.json` |
| 3. 플레이어와 씬 | 이동 물리, 충돌, 카메라, 씬 뼈대 | `player.lua`, `game.lua`, 단위 테스트와 골든 1장 |

## 3. 화면과 좌표

- 창 768x896, 렌더 배율 2 → **논리 384x448**. 타일 16px, 화면에 24x28 타일.
- 스테이지는 128x28 타일 (월드 2048x448 픽셀). 세로는 화면과 같아 카메라는
  **가로로만** 움직인다: `camX = clamp(playerX - 176, 0, 2048 - 384)`.
- 원경(배경 그림 384x448)은 카메라의 0.4배로 흐른다 (두 장 이어붙임).

## 4. 자산 규격

전부 `tools/generate_aldebaran_assets.py`가 만들고 `resources/aldebaran/`에 커밋한다.
RTP는 톱다운 규격(CharSet 보행 시트)이라 횡스크롤에 맞지 않아 쓰지 않는다.

### 4.1 카르토 시트 `karto.png` (그리드 12x2, 프레임 48x48)

엔진에 좌우 반전이 없으므로 **아랫줄에 왼쪽 보기를 굽는다** (생성기가 미러링).
프레임 번호 = 줄 x 12 + 칸 (0부터).

| 칸 | 0 | 1 | 2~5 | 6 | 7 | 8 | 9 | 10 | 11 |
|---|---|---|---|---|---|---|---|---|---|
| 내용 | 서기 A | 서기 B | 걷기 4프레임 | 점프(상승) | 낙하 | 베기 1단 | 베기 2단 | 베기 3단 | 피격 |

베기 프레임은 단검의 보라색 검기가 앞쪽에 뻗은 자세다 (2단계의 공격 판정 상자와
시각적으로 맞아야 한다). 몸통의 충돌 상자는 프레임 가운데 발 기준 **12x20**.

### 4.2 타일셋 `forest16.png` (8열, 16px)

| 묶음 | 내용 |
|---|---|
| 땅 | 진흙 땅 윗면(디더 경계), 진흙 속, 바위 턱 윗면과 속 |
| 장식 | 검은 나무 줄기 2종과 우듬지, 마른 넝쿨, 부서진 대나무, 독버섯, 잡초, 이정표 |
| 다리 | 낡은 널(온전한 것과 부서진 것), 밧줄 기둥 |
| 배경 소품 | 부서진 레굴루스 석상 (2x2), 기암 |

통행은 맵의 `collision` 배열이 정한다. 땅과 바위 턱과 다리 널만 막고, 장식은 전부
지나간다.

## 5. 스테이지 맵

`tools/generate_aldebaran_maps.py`가 `resources/maps/aldebaran_forest.json`을 만든다.
포맷은 v1 (이벤트를 싣지 않는다. 몬스터 배치는 씬의 스테이지 데이터
`scripts/games/aldebaran/stage.lua`가 든다. 이벤트 커맨드는 RPG 레이어의 것이고,
액션 게임의 배치는 코드에 더 가깝기 때문이다).

지형은 **전부 손으로 정한 자리다. 난수로 뿌리지 않는다** (port_town과 같은 규칙).

```
 x(타일)  구간
   0~ 23  숲 입구: 평탄한 진흙 길. 도입 컷씬 (2단계에서 컷씬, 이번엔 빈 길)
  24~ 47  오르막 바위 턱 셋: 점프 연습 구간. 첫 전갈거미 자리 (2단계)
  48~ 63  기암 절벽과 낡은 다리: 다리 아래는 낭떠러지(밟을 것이 없다)
  64~ 67  이정표: 체크포인트 (2단계)
  68~ 99  늑대 인간의 숲: 검은 나무가 빽빽한 내리막과 턱, 늑대 자리 (2단계)
 100~127  막다른 절벽 앞 공터: 부서진 레굴루스 석상, 짐도둑 자리 (3단계)
```

- 바닥은 y 24~27. 바위 턱은 2~4타일 높이다. **2단 점프 없이 오를 수 있는 턱**과
  **2단 점프가 필요한 턱**을 섞는다 (수치는 6.1절의 점프 높이에서 역산).
- 다리 구간(x 48~63)의 바닥은 다리 널 한 줄(y 20)뿐이고, 널 사이가 두 칸 비어 있다.
  아래로 떨어지면 목숨을 잃는다 (2단계. 이번 단계에서는 바닥 밖으로 떨어지면
  시작 지점으로 되돌린다).

## 6. 플레이어 컨트롤러 (`player.lua`)

### 6.1 물리 상수 (px/초, dt는 elapsed/1000)

| 상수 | 값 | 비고 |
|---|---|---|
| 걷기 속도 | 90 | |
| 대쉬 속도 | 190, 0.28초 | 같은 방향을 0.25초 안에 두 번 누르면 발동 |
| 중력 | 980 | |
| 점프 초속 | −330 | 최고점 약 53px (이산 적분 기준). 3타일 턱을 넘는다 |
| 2단 점프 초속 | −270 | 공중에서 한 번만. 합쳐 약 87px로 5타일 턱을 넘는다 |
| 최대 낙하 속도 | 480 | |

프레임 스파이크는 flappy와 같은 방식으로 자른다 (`dt = min(elapsed, 50) / 1000`).

**단일 터치를 위한 관성 규칙 둘** (구현하며 추가했다. 터치는 첫 손가락만 마우스로
매핑되어 패드와 점프 버튼을 동시에 누를 수 없다):

1. 공중에서 방향 입력이 없으면 수평 속도를 유지한다.
2. 지상에서 손을 뗀 직후(0.18초)의 점프는 직전 달리기 속도를 잇는다.

둘을 합치면 "달리다 손을 떼고 점프 버튼"이 키보드의 "달리며 점프"와 같은 궤적이 된다.

### 6.2 충돌

- 몸통 AABB 12x20 (발 가운데 기준). 수평으로 먼저 움직여 좌우 가장자리의 위아래
  두 점씩을 조사하고, 막히면 타일 경계에 붙인다. 수직도 같은 방식.
- 조회는 주입된 `probe(px, py) -> bool` 하나뿐이다. 씬은
  `Tilemap.IsPassable`을 픽셀 좌표로 감싸 넘기고, 단위 테스트는 표로 만든 가짜
  지도를 넘긴다.
- 맵의 좌우 끝은 벽으로 친다 (`IsPassable`의 범위 밖 false 계약이 그대로 벽이 된다).

### 6.3 상태 기계 (기획서 5.2절)

이번 단계에서 만드는 상태: **정상(서기, 걷기), 대쉬, 점프, 낙하**. 피격과 공격과
버서커는 2단계, 컷씬 잠금은 3단계다. 상태는 문자열이 아니라 표의 필드
(`onGround`, `dashLeft`, `jumpsLeft`, `facing`)로 들고, 그리기 프레임은 그 필드에서
계산한다. 상태 이름 열거는 프레임 고르기 함수 하나에만 있게 한다.

## 7. 씬 뼈대 (`game.lua`)

- `SpicaScene`이 아니라 `AldebaranScene`. 씬 이름은 `aldebaran`, 타이틀은 3단계에서
  `aldebaran_title`로 등록한다 (이번 단계에서는 메뉴에서 바로 스테이지로).
- init: 렌더 배율 2, 16px 폰트, 맵과 원경과 카르토 로드, BGM 슬롯
  (`aldebaran_forest.ogg` 없으면 `bless.ogg` 64).
- update: 입력 수집(키보드 + 가상 패드 + 점프 버튼) → `player.update` → 카메라.
- render: 원경 두 장 → `Tilemap.Draw`(ground) → 카르토 → `Tilemap.Draw`(deco 이후)
  → HUD 자리 표시 → 터치 UI.
- destroy: 배율과 폰트 원상 복구 (rpgdemo와 같은 규칙).
- ESC(뒤로가기)는 메뉴로. `INITIAL2D_DEBUG`로 좌표와 FPS.

## 8. 검수

- 단위 (`tests/lua/cases/aldebaran_player_test.lua`): 가짜 지도 위에서
  걷기 가속 없음(등속) 확인, 벽에 막힘, 턱에 올라섬, 점프 최고점이 3타일을 넘고
  4타일은 못 넘음, 2단 점프로 5타일, 공중 점프는 한 번만, 더블탭 대쉬 판정
  (0.25초 경계), 낙하 최대 속도, 바닥 밖 낙하 감지.
- 씬 (`tests/engine/scenes/aldebaran_scene.lua`): 입력 재생기로 오른쪽으로 걷고

### 구현 메모

1. **점프 초속을 −310에서 −330으로 올렸다.** 계획의 −310은 해석적 최고점(49px)
   기준이었는데, 고정 스텝(1/60초) 이산 적분은 첫 프레임에 중력이 먼저 붙어
   실측 46.5px로 3타일(48px)을 못 넘었다. 단위 테스트가 잡았다.
2. **관성 규칙 둘을 추가했다** (6.1절). 계획 단계에서는 몰랐고, 터치 조작을
   구상하다가 단일 터치(패드와 버튼을 동시에 못 누름)가 "달리며 점프"를
   불가능하게 만든다는 것을 알았다. 공중 관성과 달리기 기억(0.18초)으로 풀었다.
3. **씬 인수 테스트는 rpgdemo_scene의 구조를 따른다.** 시나리오 전체를
   Initialize 안의 고정 스텝 루프로 돌린다. `INITIAL2D_EXIT_AFTER`가 렌더 프레임
   단위라 Update에 긴 시나리오를 걸 수 없기 때문이다.
