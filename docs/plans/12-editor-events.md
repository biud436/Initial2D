# 11단계: 에디터가 이벤트를 만든다

> 이 문서는 **구상**이다. 코드는 아직 없다. 두 저장소(Initial2D, InitialEditor)에
> 걸친 작업이라, 손대기 전에 계약을 문서로 못 박아 두는 편이 싸다.
>
> 로드맵의 단계 번호로는 **11단계**다 (문서 번호 09는 검수, 10과 11은 9와 10단계가 쓴다).

**권장 모델**: Claude Fable 5. 두 저장소가 공유하는 데이터 계약을 정하는 작업이며,
한 번 굳으면 되돌리기 비싸다 ([index.md](index.md)의 모델 선정 기준).

## 1. 지금 어디까지 되어 있는가

9단계가 절반을 해 두었다. 이벤트는 이미 **순수 데이터**이고, 맵 파일이 그것을 실어 나른다.

| 조각 | 상태 | 어디 |
|---|---|---|
| 이벤트 커맨드 (17종) | ✅ 데이터로 적고 실행하고 검증한다 | `scripts/rpg/commands.lua` |
| 맵 포맷 v2의 `events` 배열 | ✅ 정의되고, 엔진이 읽고, 데모가 실제로 쓴다 | `resources/maps/port_town.json` |
| 맵 이벤트와 정의 파일 이벤트의 병합 | ✅ `id`로 합친다 (정의 파일이 이긴다) | `scripts/rpg/mapdata.lua` |
| 브리지 서버의 파일 읽기와 쓰기 | ✅ `scripts/`, `resources/` 화이트리스트 | `tools/bridge/` |
| **에디터가 v2를 여는 것** | ❌ `지원하지 않는 맵 버전` 예외 | `MapFormat.ts:253` |
| **에디터가 `events`를 보존하는 것** | ❌ 저장하면 **사라진다** | `MapFormat.ts:217` |
| **에디터의 이벤트 배치 UI** | ❌ `alert("이벤트 모드가 아직 없습니다")` | `ModeEventCommand.ts` |
| **에디터의 커맨드 편집 UI** | ❌ 없음 | (없음) |

즉 **엔진 쪽은 끝났고, 에디터 쪽이 통째로 남았다.** 그리고 지금 상태가 가장 나쁘다.
v1으로 열어 저장하면 이벤트를 조용히 잃는다.

## 2. 이 단계가 푸는 문제

> 맵 위에 NPC를 놓고, 트리거를 고르고, 대사를 적고, 저장하면, 게임에서 그 NPC에게
> 말을 걸 수 있다. **Lua를 한 줄도 쓰지 않고.**

## 3. 가장 어려운 문제: 커맨드 명세를 누가 아는가

커맨드가 17종이고 저마다 인자가 다르다. 지금 그 명세는 **세 곳**에 흩어져 있다.

1. `scripts/rpg/commands.lua`의 `SPEC` 표 (실행과 검증의 진실)
2. [10-demo-v2.md 3.2절](10-demo-v2.md)의 표 (사람이 읽는 진실)
3. 앞으로 만들 에디터의 폼 (편집의 진실)

셋이 어긋나면 에디터가 만든 이벤트를 엔진이 거부한다. 그리고 셋은 **어긋나기 쉽다**.
10단계에서 커맨드가 15종에서 17종으로 늘었을 때, 1은 코드가 강제하고 2는 사람이 고쳐야
해서 문서 쪽이 뒤늦게 따라왔다. 3이 생기면 어긋날 자리가 하나 더 는다.

### 3.1 채택: 스키마 파일 한 장 + 대조 테스트

```
resources/schema/event-commands.json      ← 두 저장소가 함께 읽는 한 장
```

```json
{
  "version": 1,
  "commands": [
    { "code": "message", "label": "대화창",
      "args": [
        { "name": "text", "type": "text", "required": true, "multiline": true },
        { "name": "name", "type": "string" },
        { "name": "face", "type": "face" }
      ],
      "waits": true },
    { "code": "if", "label": "조건 분기",
      "args": [{ "name": "cond", "type": "condition", "required": true }],
      "lists": ["thenDo", "elseDo"] }
  ],
  "conditions": [
    { "kind": "flag", "args": ["flag", "equals"] },
    { "kind": "var",  "args": ["var", "op", "value"] },
    { "kind": "item", "args": ["item", "op", "value"] }
  ]
}
```

**생성하지 않고 손으로 유지하되, Lua 단위 테스트가 `SPEC`과 대조한다.** 이 프로젝트가
이미 쓰는 방식이다 (`tests/lua/manifest.lua`가 자동 스캔이 아니라 명시적 목록인 것과 같은
이유이며, 명시적 목록은 어긋남을 **눈에 보이게** 한다).

- 커맨드를 더하고 스키마를 안 고치면 → 테스트가 깨진다
- 스키마에 없는 인자를 에디터가 쓰면 → 엔진의 `Commands.validate`가 맵을 열 때 잡는다

생성기를 두지 않는 까닭: Lua를 빌드 단계에서 돌릴 경로가 지금 없고(엔진 VM 안에서만
돈다), 생성기 자체가 또 하나의 어긋날 수 있는 조각이 된다.

### 3.2 에디터가 스키마를 어떻게 받는가

브리지의 파일 API를 그대로 쓴다. **새 엔드포인트를 만들지 않는다.**

```
GET /api/files/resources/schema/event-commands.json
```

`resources/`는 이미 화이트리스트 안이라 서버 수정이 없다. 에디터는 프로젝트를 열 때
한 번 읽어 두고, 없거나 `version`이 모르는 값이면 **이벤트 모드를 잠그고 이유를 띄운다**
(모른 채로 편집해 파일을 망가뜨리는 것보다 낫다).

### 3.3 폼은 스키마에서 만든다

커맨드 편집 화면을 17개 만들지 않는다. `args[].type` 하나당 위젯 하나를 만들고,
커맨드마다 그것을 조립한다. 필요한 위젯은 여덟이다.

| type | 위젯 | 비고 |
|---|---|---|
| `string`, `text` | 한 줄 입력 / 여러 줄 입력 | `multiline`이면 후자 |
| `number` | 숫자 입력 | |
| `boolean` | 체크박스 | |
| `enum` | 드롭다운 | `values`가 스키마에 있다 |
| `file` | 프로젝트 파일 고르기 | 브리지의 `/api/project` 목록 |
| `face` | 얼굴 고르기 (파일 + 번호) | FaceSet 격자에서 클릭 |
| `condition` | 조건 편집기 | `conditions` 표에서 만든다 |
| `list` | 중첩 커맨드 목록 | 재귀 (분기 안의 분기) |

새 커맨드가 늘어도 에디터 코드는 그대로다. 스키마 한 줄이 는다.

## 4. 마일스톤

작은 것부터. **1번은 다른 무엇보다 급하다**. 지금은 에디터로 맵을 만지는 것 자체가
데이터 손실이다.

### 마일스톤 1: 잃지 않기 (에디터, 반나절)

편집하지 못해도 좋다. **읽고, 그대로 다시 내보낸다.**

| 자리 | 지금 | 할 것 |
|---|---|---|
| `MAP_FORMAT_VERSION = 1` | 상수 하나 | `SUPPORTED = [1, 2]`, 내보내기는 항상 2 |
| `assertMapFileV1` | `v1만 지원` 예외 | 1과 2를 모두 받아들인다 |
| `importMapV1` | `events`를 버린다 | 문서에 그대로 실어 둔다 (편집하지 않음) |
| `exportMapV1` | v1 필드만 만들어 반환 | 실어 둔 `events`를 그대로 내보낸다 |
| `test/fixtures/` | v1 픽스처 하나 | `sample_v2.json` 사본 + 왕복에서 `events`가 남는지 |

완료 기준: **에디터로 `port_town.json`을 열어 타일 한 칸을 칠하고 저장해도, 데모의
짐 상자 이벤트가 그대로 돈다.**

### 마일스톤 2: 놓기 (에디터)

이벤트 모드. `ModeEventCommand`의 `alert`를 진짜 화면으로 바꾼다.

- 맵 격자 위에 이벤트 아이콘 (외형이 있으면 CharSet의 정면 프레임, 없으면 표식)
- 클릭으로 놓기, 끌어서 옮기기, Delete로 지우기
- 속성 창: `id`, 트리거(action / touch / auto / parallel), 외형(CharSet 파일과 번호), 방향
- **`id` 중복과 좌표 충돌은 저장 전에 막는다** (엔진은 같은 칸의 두 이벤트를 정의하지 않는다)
- 타일맵의 undo 스택(`TilemapHistory`)과 **같은 스택**에 넣는다. 두 개의 되돌리기는 혼란스럽다

### 마일스톤 3: 적기 (에디터)

커맨드 목록 편집기. 3.3절의 스키마 기반 폼.

- 목록은 트리다. 분기(`choice.branches`, `if.thenDo/elseDo`)는 들여쓰기로 보인다
- 추가 / 삽입 / 삭제 / 위아래 이동 / 복사와 붙여넣기
- 미리보기: 대화창 커맨드는 게임에서 어떻게 접히는지 폭을 맞춰 보여 준다 (선택)
- 저장 전 검증: 스키마의 `required`를 확인하고, 실패하면 **어느 자리인지**를
  엔진과 같은 경로 표기로 알린다 (`events[2].commands[3].branches[1][2]`)

### 마일스톤 4: 옮기기와 왕복 (엔진 저장소)

지금 데모의 이벤트 17종은 `scripts/maps/*.lua`에 있다. 에디터로 편집하려면 맵 파일로
옮겨야 한다.

- `tools/export_events.py` 또는 엔진 안의 덤프: 정의 파일의 이벤트를 맵 JSON의
  `events`로 내보낸다. `script` 커맨드와 `wander` 같은 아직 데이터가 아닌 속성은
  **옮기지 않고 정의 파일에 남긴다**. 무엇이 남았는지 도구가 알린다
- 옮긴 뒤 인수 시나리오가 **한 줄도 안 고치고** 통과하는지 확인한다 (9단계 마일스톤 1과
  같은 방식의 회귀)
- 브리지 왕복을 사람이 실제로 눌러 본다

## 5. 남은 데이터화: 무엇이 아직 Lua에만 있는가

이벤트를 전부 에디터로 옮기려면 아래가 데이터가 되어야 한다. 지금은 정의 파일의
Lua 필드다.

| 속성 | 지금 | 데이터로 옮길 때 |
|---|---|---|
| `wander` (배회 범위와 간격) | Lua 표 | 그대로 JSON 객체로. 어렵지 않다 |
| `speed`, `through`, `solid` | Lua 필드 | 그대로 |
| `charset` | `{ file, index }` | 그대로. 단 파일 경로가 `Assets.npcCharset()` 호출이라 **RTP 유무에 따라 달라진다**. JSON에는 논리 이름을 적고 엔진이 고르게 해야 한다 |
| `script` 커맨드의 함수 | 정의 파일의 `scripts` 표 | **옮기지 않는다.** 이것이 탈출구의 값어치다 |
| 맵의 `bgm`, `start` | 정의 파일 | 맵 파일의 속성으로 옮길 수 있다 (마일스톤 4의 뒤) |

`charset`의 RTP 문제가 유일하게 설계가 필요한 자리다. 제안: 맵 파일에는
`"charset": { "set": "npc", "index": 3 }`처럼 **논리 이름**을 적고,
`scripts/rpg/assets.lua`가 그것을 실제 경로로 푼다. 에디터는 논리 이름의 목록을
브리지에서 받는다 (`/api/project`에 한 줄 추가).

## 6. 위험

1. **텍스트가 데이터에 들어간다.** 대사에는 줄바꿈과 따옴표와 한글이 들어간다.
   JSON은 이미 다 다루지만, 에디터의 입력 칸이 `\n`을 어떻게 저장하는지 왕복 테스트가
   필요하다. 픽스처에 줄바꿈이 든 대사를 하나 넣어 둔다.
2. **두 사람이 같은 맵을 만진다.** 에디터가 열어 둔 사이에 브리지의 파일 감시가
   외부 변경을 알린다 (`/ws`는 이미 그 이벤트를 보낸다). 그때 무엇을 할지는 정해져
   있지 않다. 최소한 "파일이 바뀌었다"를 알리고 덮어쓰기 전에 묻는다.
3. **스키마 버전.** 커맨드가 늘거나 인자가 바뀌면 `version`을 올린다. 에디터는 모르는
   버전을 만나면 잠근다. 맵 파일 자체의 버전(v2)과는 다른 축이다.
4. **범위가 커지는 것.** 마일스톤 1만으로도 값어치가 있다. 2와 3은 각각 따로 서며,
   마일스톤 3 없이도 "에디터로 배치하고 대사는 Lua로"가 성립한다.
